# DMP Trajectory Streaming (Flutter)

## Overview
The Flutter implementation of DMP Trajectory Streaming is responsible for breaking down a validated `DmpResult` into smaller segments (chunks) and asynchronously streaming them to the ESP32 physical hardware over Bluetooth Low Energy (BLE). This enables the robot to execute fluid, continuous motion generated by the Dynamic Movement Primitives pipeline.

## Architectural Components

### 1. Trajectory Streaming State Model
**File:** `lib/features/dmp_preview/domain/models/trajectory_streaming_state.dart`
Provides a robust state machine for the streaming process:
- `idle`: Not streaming.
- `preparing`: Chunking trajectory.
- `sendingBegin`: Transmitting setup command to ESP32.
- `streaming`: Actively transmitting data chunks.
- `sendingEnd`: Stream complete; transmitting teardown command.
- `ready` / `completed`: Firmware successfully buffered/executed the trajectory.
- `failed` / `aborted`: Error or user cancellation.

### 2. DmpTrajectoryStreamer (Service & Notifier)
**File:** `lib/features/dmp_preview/domain/services/dmp_trajectory_streamer.dart`
The core asynchronous stream engine. It relies heavily on staggered asynchronous execution instead of arbitrarily timed sleeps or blocking the UI thread.
- **Safety Guarantee:** The streamer is aware of the ESP32 firmware limits (50-sample ring buffer).
- **Flow Control Mechanism:** Because we rely on `withoutResponse: true` on BLE and do not receive immediate ACK telemetry back for each chunk, the streamer algorithm ensures the buffer never overflows. It mathematically determines when the `i-2` chunk finishes its physical execution, and safely queues the `i` chunk. This maintains a healthy backlog on the hardware buffer while avoiding data loss.
- **Dependencies:** Interacts directly with `HardwareRobotRepository.sendCommand` using Command IDs 610 (`TRAJECTORY_CHUNK`) and 611 (`TRAJECTORY_CONTROL`).

### 3. Streamer Provider
**File:** `lib/features/dmp_preview/presentation/providers/dmp_streamer_provider.dart`
Exposes the `DmpTrajectoryStreamer` state directly to the Flutter widget tree using Riverpod.

### 4. UI Integration (Dmp Preview Screen)
**Files:** `dmp_preview_screen.dart` and `dmp_preview_widgets.dart`
The `Approve Motion` button has been transitioned to `RUN DRY-RUN` when connected to physical hardware. Clicking this initializes the asynchronous streaming process.
The user is provided with a real-time `DryRunStreamingStatus` interface presenting:
- Chunk transmission progress.
- Sample transmission progress.
- Firmware execution state (Buffering/Executing).
- Ability to `ABORT DRY-RUN` mid-stream.
